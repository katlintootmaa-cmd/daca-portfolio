# Week 10: Portfolio Organization and Publishing

Eestikeelne versioon: [README.md](README.md)

## Business Problem

During 10 weeks I created many learning materials, analyses, and project files. The portfolio needed to be organized so that a recruiter, mentor, or future colleague could quickly find the most important projects and understand their business value.

## Approach

I organized the portfolio homepage, selected the strongest projects, and focused on making each project answer three questions:

- what problem the project solves;
- which tools and methods I used;
- what the result or learning outcome was.

## Main Outputs

- Main README that introduces me as a Junior Data Analyst.
- Selected projects list with short descriptions and links.
- More consistent README structure for key projects.
- Contact information: email, LinkedIn, and location.

## Technical Stack

- GitHub
- Markdown
- Power BI, SQL, Python, and Pandas for documenting previous projects

## How to Use

1. Start from the repository homepage: [../README.md](../README.md).
2. Open the "Selected Projects" section.
3. Go to a project README and review the business problem, key findings, screenshots, and run instructions.

## Lessons Learned and Challenges

I learned that a portfolio is not just a collection of files. A strong portfolio needs to tell a clear story: what I can do, what problems I solved, and how my work creates value.

The main challenge was choosing the most important projects and describing them so that the reader can understand within 30-60 seconds why the project matters.

## AI Usage

I used AI to audit the README structure and polish wording. The final project choices, contact information, and learning reflections are based on my own portfolio work.
