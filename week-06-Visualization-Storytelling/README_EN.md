# Week 6: Visualization Data

Estonian version: [README.md](README.md)

This week I learned how to turn a dashboard into a clearer data story, not only a collection of charts. I understood that good visualization does not only show what happened in the data, but also helps the viewer understand why it matters and what should be done next.

First, I learned the importance of annotations. I understood that titles, subtitles, axis labels, data labels, reference lines, and callouts help guide the viewer's attention to the most important information. If a chart only has lines or bars, the viewer has to figure out what to notice. With annotations, it is possible to clearly show which point is important, where a target was exceeded, or which change needs explanation.

Second, I learned that annotations should not be overused. If every number and every point is separately highlighted, the visualization becomes difficult to read. I understood that an annotation should support the main message, not simply add more text to the chart. It is important to choose only the notes that help the viewer reach the right conclusion faster.

Third, I learned the principles of data storytelling. I understood that a single number is not yet a story. For example, saying that revenue grew needs context: why it happened, whether it is a good result, and what should be done with that knowledge. The "So what?" test helped me think more deeply, so that every data point should lead to meaning or a recommendation.

I learned to use the structure of a data story: context, data, and narrative. First, it is necessary to explain why the topic matters, then show what the data says, and finally explain what it means. This helped me understand that an analyst's work does not end with making a chart, but must help turn data into a decision or action.

I also learned how to adapt a dashboard to the audience. I understood that the same data does not mean the same thing to everyone. A CEO wants to see growth, strategy, and investment potential. An operations manager wants to know what needs to change in inventory, stores, or daily work. Marketing needs information about channels, campaigns, and ROI. This means that dashboard content, emphasis, and wording must depend on who the dashboard is shown to.

Through the UrbanStyle example, I learned how to combine annotations, data storytelling, and audience needs into one whole. For an investor dashboard, showing only revenue is not enough. It is necessary to show a growth story: whether the company is growing, what drives that growth, which channels or products are strong, and which next steps would be reasonable.

In summary, this week I learned to:

- add meaningful annotations to charts;
- separate important annotations from unnecessary information;
- use titles, subtitles, reference lines, data labels, and callouts;
- turn individual numbers into a data story;
- use the "So what?" test to move from data to conclusion;
- think about dashboard needs based on the target audience;
- adapt the same dataset story for CEO, operations, and marketing perspectives;
- see a dashboard as a communication and decision-making tool.

This week I understood that a good dashboard is not finished when all charts are in place. It is finished when the viewer quickly understands the main message and can make a decision based on it. Data visualization is therefore not only a technical skill, but also a skill of explanation and storytelling.
